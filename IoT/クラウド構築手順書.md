# クラウド構築手順書（AWS IoT Core 連携）

[重要] 本書は ESP32 + LocalServer を AWS IoT Core（クラウド MQTT ブローカー）に接続するための  
**人間が実際に手を動かして構築する手順書**である。  
理由: セキュリティ設定・鍵管理・証明書配備等、コードだけでは把握できない操作手順を一元化するため。

[参照]
- アーキテクチャ決定: `設計議事録20260520.md §2`
- IF 仕様: `IF仕様書.md §5`
- 未完了タスク: `todo.md ### 012.`

## 0. 全体概要

### 0.1 採用アーキテクチャ（Option B: ESP32 直接接続方式）

```text
═══════════════════════════════════════════════════════════════
 [クラウドモード]
═══════════════════════════════════════════════════════════════

 ESP32-S3                            AWS IoT Core
   │  TLS 8883                        (ap-northeast-1 東京)
   │  X.509 クライアント証明書         ┌──────────────────────┐
   │  AES-256-GCM payload(k-device)   │ MQTT Broker          │
   └─────────────────────────────────►│ IoT Policy           │
                                      │ IoT Rules Engine     │
 LocalServer (Node.js/TypeScript)     │   └─► Lambda (任意)  │
   │  TLS 8883                        │                      │
   │  X.509 クライアント証明書         │                      │
   └─ subscribe ──────────────────────►                      │
                                      └──────────────────────┘
   │
   └─► SecretCore (Rust) ← 変更なし（k-device 導出・payload 復号）

═══════════════════════════════════════════════════════════════
 [ローカルモード（フォールバック）]
═══════════════════════════════════════════════════════════════

 ESP32-S3                            Mosquitto (172.17.1.100:8883)
   │  TLS 8883                        │
   │  ID/Password                     │
   │  AES-256-GCM payload            │
   └─────────────────────────────────►│

 LocalServer (Node.js/TypeScript)     │
   └─ subscribe ──────────────────────►

═══════════════════════════════════════════════════════════════
 モード切替: ESP32 NVS brokerMode=local|cloud
            LocalServer .env CLOUD_MQTT_ENABLED=true|false
═══════════════════════════════════════════════════════════════
```

### 0.2 各モジュールの役割

| モジュール | 場所 | クラウドモードでの役割 |
|---|---|---|
| **ESP32-S3** | デバイス（フィールド）| X.509 証明書で AWS IoT Core に直接 TLS 8883 接続。AES-256-GCM 暗号化 MQTT メッセージを Publish |
| **AWS IoT Core** | クラウド（ap-northeast-1）| MQTT ブローカー本体。X.509 証明書で接続元を認証し、IoT Policy でトピック単位に認可 |
| **IoT Policy** | AWS IoT Core 内 | certARN（証明書）に対して Connect/Publish/Subscribe/Receive を topic 単位で許可する JSON ポリシー |
| **IoT Rules Engine** | AWS IoT Core 内 | topic フィルタ条件に合致したメッセージを Lambda / DynamoDB / S3 等にルーティング（任意）|
| **Lambda** | AWS | IoT Rules から呼ばれるサーバーレス処理（メッセージ加工・DB書込み等）任意追加 |
| **LocalServer** | Windows PC / サーバー | AWS IoT Core を subscribe してクラウド経由 MQTT メッセージを受信。既存 REST API / Web UI はそのまま |
| **SecretCore** | Windows PC | 変更なし。DPAPI → k-device 導出・AES-256-GCM 復号を担う |
| **Mosquitto** | Windows PC | ローカルモード時の MQTT ブローカー。クラウドモードでも LocalServer は subscribe を維持 |
| **LittleFS /certs/** | ESP32 ファイルシステム | X.509 証明書 3 ファイルを保管（aws-device-cert.pem / aws-private-key.pem / AmazonRootCA1.pem）|

### 0.3 なぜこのアーキテクチャを選んだか（選定基準）

| 選定基準 | 採用理由 |
|---|---|
| **ローカル実装を崩さない** | ESP32 の AES-256-GCM 暗号化・SecretCore 鍵管理・LocalServer API を一切変更しない |
| **いつでもローカルに戻せる** | NVS `brokerMode=local` + `CLOUD_MQTT_ENABLED=false` で 2 分以内にフォールバック可能 |
| **AWS IoT Core を選んだ理由** | 東京リージョン(ap-northeast-1)、フルマネージド、X.509 ネイティブ、Lambda/Cognito との統合、無料枠（12ヶ月 500K msg/月）|
| **Bridge 方式（Option A）を不採用にした理由** | LocalServer を中継ルータにすると単一障害点が増える。ESP32 直接接続が AWS IoT Core 本来の設計に合致 |
| **Cognito を使わない理由** | Cognito は Web/Mobile ユーザー向け。デバイス・サーバーの常時接続には X.509 が適切 |
| **ID/Password でなく X.509 にした理由** | AWS IoT Core は ID/Password 認証を直接サポートしない（Custom Authorizer Lambda が必要になりコスト増）|

## 2. AWS 側の構築手順

### 2.1 AWS IoT Core エンドポイントの取得

AWS IoT Core に接続するための custom endpoint を取得する。エンドポイントはアカウントごとに固定値。

```bash
# AWS CLI でエンドポイントを取得
aws iot describe-endpoint --endpoint-type iot:Data-ATS --region ap-northeast-1

# 出力例:
# {
#   "endpointAddress": "xxxxxxxxxx.iot.ap-northeast-1.amazonaws.com"
# }
```

**→ 取得した `endpointAddress` を後の `.env` に設定する（§4.1 参照）**

### 2.2 ESP32 用 X.509 デバイス証明書の発行

AWS IoT Core で ESP32 用の証明書・秘密鍵・Root CA を発行する。

#### 2.2.1 AWS コンソールで発行する方法（GUI）

1. AWS コンソール → **IoT Core** → **セキュリティ** → **証明書**
2. 「証明書の作成」→「1 クリックで証明書を作成」を選択
3. 以下のファイルをダウンロード（この時点以外でダウンロード不可）:
   - `xxxxxxxxxx-certificate.pem.crt` → `aws-device-cert.pem` として保存
   - `xxxxxxxxxx-private.pem.key` → `aws-private-key.pem` として保存
   - `AmazonRootCA1.pem`（ルート CA）→ そのまま保存
4. 証明書を「有効化」する

#### 2.2.2 AWS CLI で発行する方法

```bash
# 作業ディレクトリを作成
mkdir -p C:\mydata\project\myproject\certs\esp32
cd C:\mydata\project\myproject\certs\esp32

# 証明書・鍵ペア・Root CA を一括発行
aws iot create-keys-and-certificate \
  --set-as-active \
  --certificate-pem-outfile aws-device-cert.pem \
  --public-key-outfile aws-public-key.pem \
  --private-key-outfile aws-private-key.pem \
  --region ap-northeast-1

# 出力例（重要: certificateArn と certificateId を控えておく）:
# {
#   "certificateArn": "arn:aws:iot:ap-northeast-1:123456789:cert/xxxxxxxxxxxxxxxx",
#   "certificateId": "xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx",
#   ...
# }

# Amazon Root CA のダウンロード
curl -o AmazonRootCA1.pem https://www.amazontrust.com/repository/AmazonRootCA1.pem
```

**→ `certificateArn` を控える（IoT Policy のアタッチに使用）**

[セキュリティ注意] `aws-private-key.pem` は再発行不可。必ず安全な場所に保管し、Git には絶対に含めない。

### 2.3 LocalServer 用 X.509 デバイス証明書の発行

ESP32 用とは**別の証明書**を LocalServer 用に発行する。

```bash
# 作業ディレクトリ
mkdir -p C:\mydata\project\myproject\certs\localserver
cd C:\mydata\project\myproject\certs\localserver

# 証明書発行
aws iot create-keys-and-certificate \
  --set-as-active \
  --certificate-pem-outfile localserver-cert.pem \
  --public-key-outfile localserver-public-key.pem \
  --private-key-outfile localserver-private.key \
  --region ap-northeast-1

# Root CA はESP32と共通のものを使用可（コピーしておく）
copy C:\mydata\project\myproject\certs\esp32\AmazonRootCA1.pem AmazonRootCA1.pem
```

### 2.4 IoT Policy の作成（ESP32 用）

ESP32 が Publish できる最小権限ポリシーを作成する。

```bash
# ポリシーファイルの作成（実行前にファイルを作成する）
# ファイル: esp32-policy.json
```

`esp32-policy.json` の内容:
```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "iot:Connect",
      "Resource": "arn:aws:iot:ap-northeast-1:*:client/esp32s3-*"
    },
    {
      "Effect": "Allow",
      "Action": [
        "iot:Publish",
        "iot:Subscribe",
        "iot:Receive"
      ],
      "Resource": [
        "arn:aws:iot:ap-northeast-1:*:topic/esp32lab/*",
        "arn:aws:iot:ap-northeast-1:*:topicfilter/esp32lab/*"
      ]
    }
  ]
}
```

```bash
# ポリシーの作成
aws iot create-policy \
  --policy-name "esp32-iot-policy" \
  --policy-document file://esp32-policy.json \
  --region ap-northeast-1

# 証明書にポリシーをアタッチ（certificateArn は §2.2 で控えたもの）
aws iot attach-policy \
  --policy-name "esp32-iot-policy" \
  --target "arn:aws:iot:ap-northeast-1:123456789:cert/xxxxxxxx" \
  --region ap-northeast-1
```

### 2.5 IoT Policy の作成（LocalServer 用）

LocalServer が Subscribe できる最小権限ポリシーを作成する。

`localserver-policy.json` の内容:
```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "iot:Connect",
      "Resource": "arn:aws:iot:ap-northeast-1:*:client/localserver-*"
    },
    {
      "Effect": "Allow",
      "Action": [
        "iot:Subscribe",
        "iot:Receive"
      ],
      "Resource": [
        "arn:aws:iot:ap-northeast-1:*:topic/esp32lab/*",
        "arn:aws:iot:ap-northeast-1:*:topicfilter/esp32lab/*"
      ]
    },
    {
      "Effect": "Allow",
      "Action": "iot:Publish",
      "Resource": "arn:aws:iot:ap-northeast-1:*:topic/esp32lab/call/*"
    }
  ]
}
```

```bash
# ポリシーの作成
aws iot create-policy \
  --policy-name "localserver-iot-policy" \
  --policy-document file://localserver-policy.json \
  --region ap-northeast-1

# 証明書にポリシーをアタッチ（LocalServer の certificateArn）
aws iot attach-policy \
  --policy-name "localserver-iot-policy" \
  --target "arn:aws:iot:ap-northeast-1:123456789:cert/yyyyyyyy" \
  --region ap-northeast-1
```

### 2.6 IoT Thing の作成（任意・推奨）

Thing（デバイス論理エンティティ）を作成し証明書に紐付けると、AWS コンソールでデバイスを管理しやすくなる。

```bash
# Thing の作成
aws iot create-thing \
  --thing-name "esp32s3-001" \
  --region ap-northeast-1

# Thing に証明書をアタッチ
aws iot attach-thing-principal \
  --thing-name "esp32s3-001" \
  --principal "arn:aws:iot:ap-northeast-1:123456789:cert/xxxxxxxx" \
  --region ap-northeast-1
```

### 2.7 設定の確認

```bash
# 証明書一覧の確認
aws iot list-certificates --region ap-northeast-1

# ポリシー一覧の確認
aws iot list-policies --region ap-northeast-1

# 証明書にアタッチされたポリシーの確認
aws iot list-attached-policies \
  --target "arn:aws:iot:ap-northeast-1:123456789:cert/xxxxxxxx" \
  --region ap-northeast-1

# Thing 一覧
aws iot list-things --region ap-northeast-1
```

## 3. ESP32 側の構築手順

### 3.1 証明書の書込み（LittleFS /certs/）

ESP32 の LittleFS ファイルシステムに X.509 証明書を書込む。

**書込みが必要なファイル:**

| ファイル名 | 内容 | 取得元 |
|---|---|---|
| `/certs/aws-device-cert.pem` | ESP32 用デバイス証明書 | §2.2 で発行 |
| `/certs/aws-private-key.pem` | ESP32 用秘密鍵 | §2.2 で発行（再発行不可）|
| `/certs/AmazonRootCA1.pem` | Amazon Root CA | §2.2 でダウンロード |

**書込み方法（現行: LocalServer 経由 REST API）:**

```bash
# LocalServer が起動している状態で書込む
# エンドポイント: POST /api/device/certs（012-0005 で実装予定）
# 実装前は PlatformIO の LittleFS ファイルシステムアップロード機能を使用

# PlatformIO でファイルシステムをアップロード（data/ フォルダにファイルを配置後）
cd IoT/ESP32
# IoT/ESP32/data/certs/ に証明書ファイルを配置（ローカルのみ・Git 除外）
pio run --target uploadfs --environment esp32s3_secure
```

[注意] `IoT/ESP32/data/certs/` は `.gitignore` で除外する必要がある（秘密鍵を含むため）。

### 3.2 NVS ブローカーモードの設定

ESP32 の NVS（Non-Volatile Storage）に接続先設定を書込む。

**AP モード設定 UI 経由（推奨）:**
1. ESP32 の BOOT ボタンを長押し → AP モード起動（`esp32lab-setup` AP が出現）
2. PC / スマートフォンで `esp32lab-setup` に接続（パスワード: `.env` の `AP_PASSWORD`）
3. ブラウザで `http://192.168.4.1/` → 設定 UI を開く
4. 「MQTT ブローカー設定」で以下を設定:
   - `brokerMode`: `cloud`
   - `cloudEndpoint`: `<endpoint>.iot.ap-northeast-1.amazonaws.com`（§2.1 で取得）
5. 保存 → 再起動

**NVS の確認（デバッグ時）:**
```bash
# シリアルモニタで起動ログを確認
pio device monitor --baud 115200 --environment esp32s3_secure

# 期待する出力例:
# [MQTT] brokerMode=cloud
# [MQTT] endpoint=xxxxxxxxxx.iot.ap-northeast-1.amazonaws.com
# [MQTT] Connecting with X.509 certificate...
# [MQTT] Connected to AWS IoT Core
```

## 4. LocalServer 側の構築手順

### 4.1 .env ファイルの設定

`IoT/LocalServer/.env`（Git 除外済み）に以下を追記する。

```dotenv
# ─────────────────────────────────────────────────────────
# AWS IoT Core 設定（クラウドモード）
# ─────────────────────────────────────────────────────────

# クラウド接続 ON/OFF フラグ
# true: AWS IoT Core を subscribe（クラウドモード）
# false: Mosquitto のみ subscribe（ローカルモード）
CLOUD_MQTT_ENABLED=false

# クラウドプロバイダー（現在は aws-iot-core のみ対応）
CLOUD_PROVIDER=aws-iot-core

# AWS IoT Core エンドポイント（§2.1 で取得したアドレス）
# 例: xxxxxxxxxx.iot.ap-northeast-1.amazonaws.com
AWS_IOT_ENDPOINT=xxxxxxxxxx.iot.ap-northeast-1.amazonaws.com

# LocalServer の clientId（AWS IoT Policy で Connect を許可した値と一致させる）
AWS_IOT_CLIENT_ID=localserver-mypc

# LocalServer 用 X.509 証明書ファイルパス（§2.3 で発行・絶対パスで記載）
AWS_IOT_CLIENT_CERT_PATH=C:\mydata\project\myproject\certs\localserver\localserver-cert.pem
AWS_IOT_PRIVATE_KEY_PATH=C:\mydata\project\myproject\certs\localserver\localserver-private.key
AWS_IOT_CA_CERT_PATH=C:\mydata\project\myproject\certs\localserver\AmazonRootCA1.pem

# ─────────────────────────────────────────────────────────
# (以下既存設定は変更しない)
# ─────────────────────────────────────────────────────────
```

[セキュリティ厳守]
- `.env` は Git に絶対にコミットしない（`.gitignore:10` で除外確認済み）
- 証明書ファイルパスにはリポジトリ外の絶対パスを使用する
- `.env.sample` に構造（キー名・コメント）のみ記載し、実値は書かない

### 4.2 npm パッケージの追加

```bash
cd IoT/LocalServer
nvm use 22

# AWS IoT Device SDK v2 の追加（012-0005 実装時）
npm install aws-iot-device-sdk-v2

# インストール確認
npm list aws-iot-device-sdk-v2
```

### 4.3 LocalServer の起動・確認

```bash
cd IoT/LocalServer
nvm use 22
npm run start

# クラウドモード時の期待ログ:
# [CloudMQTT] CLOUD_MQTT_ENABLED=true
# [CloudMQTT] Connecting to xxxxxxxxxx.iot.ap-northeast-1.amazonaws.com:8883
# [CloudMQTT] Connected. clientId=localserver-mypc
# [CloudMQTT] Subscribed to esp32lab/#

# ヘルスチェック
curl http://localhost:3100/api/health
```

## 5. 接続試験手順

### 5.1 AWS IoT Core コンソールで MQTT テスト

AWS コンソールの MQTT テストクライアントで疎通確認できる。

1. AWS コンソール → **IoT Core** → **MQTT テストクライアント**
2. 「トピックをサブスクライブ」→ `esp32lab/#` を入力 → 「サブスクライブ」
3. ESP32 をクラウドモードで起動 → 起動通知が届くことを確認

### 5.2 CLI での MQTT 受信確認

```bash
# AWS CLI v2 でトピックを購読して確認（別途 mosquitto_sub 相当は AWS CLI に標準なし）
# → コンソールの MQTT テストクライアントを使用するか、aws-iot-device-sdk-v2 のサンプルを使用

# AWS IoT Core へ Publish テスト（CLI から）
aws iot-data publish \
  --topic "esp32lab/notice/status/test" \
  --payload '{"test":"hello"}' \
  --region ap-northeast-1
```

### 5.3 E2E 試験チェックリスト

| 試験項目 | 確認方法 | 合格条件 |
|---|---|---|
| ESP32 → AWS IoT Core 接続 | シリアルログ | `Connected to AWS IoT Core` が出力 |
| ESP32 Publish → コンソール受信 | AWS MQTT テストクライアント | `esp32lab/notice/status/<name>` に起動通知が届く |
| LocalServer subscribe 受信 | LocalServer ログ | `[CloudMQTT] message received: esp32lab/...` が出力 |
| AES-256-GCM 復号 | LocalServer ログ | 復号成功（既存ロジックそのまま）|
| ローカルモードフォールバック | 後述 §6 | ESP32 → Mosquitto に切替後も通信継続 |

## 6. フォールバック手順（Cloud → Local）

[重要] ESP32 と LocalServer を**必ず同時**にローカルモードへ切り替えること。  
片方だけ切り替えると通信が分断される。

### 手順 1: ESP32 をローカルモードへ

1. ESP32 を AP モードで起動（BOOT ボタン長押し）
2. `esp32lab-setup` AP に接続 → `http://192.168.4.1/`
3. `brokerMode=local` に変更 → 保存 → 再起動
4. シリアルモニタで `[MQTT] brokerMode=local` / `Connected to Mosquitto` を確認

### 手順 2: LocalServer をローカルモードへ

```bash
# IoT/LocalServer/.env を編集
# CLOUD_MQTT_ENABLED=true → false に変更

# LocalServer を再起動
cd IoT/LocalServer
npm run start

# 確認ログ:
# [CloudMQTT] CLOUD_MQTT_ENABLED=false, skip cloud connection
# [LocalMQTT] Connected to Mosquitto at 172.17.1.100:8883
```

### フォールバック後の確認

```bash
# LocalServer ヘルスチェック
curl http://localhost:3100/api/health

# ESP32 からの Mosquitto メッセージが LocalServer に届くことを確認
```

| 項目 | 規則 | 参照 |
|---|---|---|

| raw k-device | クラウドへ送信しない。AES-256-GCM 暗号化したまま MQTT Publish | `IF仕様書.md §5.3` |
| AWS 認証情報 | `~/.aws/credentials` のみ。ソースに Access Key / Secret Key を書かない | `IF仕様書.md §5.3` |
| IoT Policy | 最小権限原則。不要な topic の Publish/Subscribe を許可しない | `IF仕様書.md §5.4` |
| LittleFS /certs/ | Git 除外設定を確認してからファイルをコミットする | `IF仕様書.md §5.4` |
| eFuse / Secure Boot | クラウドトリガで実行しない。ProductionTool ローカル工程のみ | `IF仕様書.md §5.3` |

## 8. トラブルシューティング

| 症状 | 原因候補 | 対処 |
|---|---|---|
| ESP32 が AWS IoT Core に接続できない | 証明書が LittleFS に未配備 / 有効化されていない | `aws iot describe-certificate --certificate-id <id>` で `ACTIVE` を確認 |
| ESP32 が AWS IoT Core に接続できない | IoT Policy が certARN にアタッチされていない | `aws iot list-attached-policies --target <certARN>` で確認 |
| ESP32 が接続できない | エンドポイントが間違っている | `aws iot describe-endpoint --endpoint-type iot:Data-ATS` で再確認 |
| LocalServer が subscribe できない | 証明書パスが `.env` に未設定 / ファイルが存在しない | `AWS_IOT_CLIENT_CERT_PATH` / `AWS_IOT_PRIVATE_KEY_PATH` のパスを確認 |
| メッセージが LocalServer に届かない | IoT Policy に Subscribe/Receive がない | `localserver-policy.json` を再確認 |
| 復号エラー（AES-256-GCM）| クラウドモードで k-device がない | SecretCore / `.env` の鍵設定を確認 |
| LocalServer 起動時クラッシュ | `aws-iot-device-sdk-v2` 未インストール | `npm install aws-iot-device-sdk-v2` |

### 9.1 AWS IoT Core の課金モデル

AWS IoT Core は**従量課金**。試験時以外はクラウドモードを **OFF** にすることで課金を最小化する。

| 課金項目 | 単価（2024 年時点）| 無料枠（初回 12ヶ月）|
|---|---|---|
| **接続（Connectivity）** | $0.042 / 100万接続分 | 500,000 分/月 |
| **メッセージング** | $1.00 / 100万メッセージ（5KB単位）| 500,000 メッセージ/月 |
| **Rules Engine** | $0.15 / 100万ルール実行 | 250,000 回/月 |

**試算例（ESP32 1台を常時接続した場合）:**
- 接続時間: 24時間 × 30日 = 43,200 分/月 → 無料枠内（500,000分/月）
- メッセージ数: 1分に1回 = 43,200 メッセージ/月 → 無料枠内（500,000/月）
- → 無料枠期間中は**通常のテスト利用であれば課金ゼロ**

[注意] 無料枠は AWS アカウント開設から **12ヶ月のみ**。期間終了後は課金が発生する。

### 9.2 試験時以外はクラウドモードを OFF にする
