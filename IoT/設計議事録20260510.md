## 2. 問題と解決

### 2.1 `k-device` 不一致 / 欠落
- 症状:
  - `test:7052` 実施時に `securePing` が失敗した。
  - ESP32 側で `loadKDeviceBytes failed. key size must be 32. actual=0` が確認された。
  - LocalServer 側では復号エラーが発生した。
- 原因:
  - [重要] 直接原因は `k-device` の不一致 / 欠落であり、ESP32 が MQTT 暗号通信を完了できない状態だった。
  - [補足] `otadata invalid` / `confirmCurrentAppIfNeeded failed` は残課題として分離した。理由: AP 復旧後に `beta.37` 起動、MQTT 接続、`securePing` は成立したため、`7052` 完了条件とは別管理にできる。
- 解決:
  - AP モードで LocalServer 現行 `k-device` を再同期した。
  - raw key は表示せず、32 byte 長と fingerprint のみで一致確認した。
  - `7052` 再試験で、正規 `keyDeviceSet` 後と改ざん署名 publish 後の両方で `securePing=OK` を確認した。
- 正本:
  - `問題点記録書.md` `#0035`
  - `試験記録書.md` `7052`

### 2.2 改ざん署名試験の不安定要因
- 症状:
  - Base64 末尾改ざんでは、デコード後の HMAC 実バイト列が変化しない可能性があった。
- 原因:
  - Base64 末尾は padding や未使用 bit の影響を受ける場合がある。
- 解決:
  - [厳守] 改ざん署名試験では Base64 先頭側の有効文字を変更する方針へ修正した。
  - `7052` で改ざん鍵 fingerprint と正規鍵 fingerprint を分けて記録できるようにした。

### 2.3 `Wi-Fi_lab` AP 接続不良
- 症状:
  - `Wi-Fi_lab` で ESP32 AP が見えるが接続できない状態があった。
- 原因:
  - Realtek USB Wi-Fi アダプタの帯域幅設定が `20_40MHz` のとき、ESP32 SoftAP の `WPA2-Personal / CCMP` とのネゴシエーションが不安定だった。
- 解決:
  - `Wi-Fi_lab` の `Bandwidth` を `20MHz Only` へ変更した。
  - AP のパスワード削除や暗号緩和は行わなかった。
- 正本:
  - `問題点記録書.md` `#0034`

### 2.4 PlatformIO `cp932` デコードエラー
- 症状:
  - `beta.38` OTA 準備時に PlatformIO の `checkprogsize` で `UnicodeDecodeError` が発生した。
- 原因:
  - 日本語コメント入りのパーティションCSVを、Windows 既定の `cp932` として読もうとした。
- 解決:
  - `PYTHONUTF8=1` / `PYTHONIOENCODING=utf-8` を Python 子プロセスへ渡してビルドした。
  - `cmd /c "set PYTHONUTF8=1&& set PYTHONIOENCODING=utf-8&& ..."` の形で成功を確認した。
- 正本:
  - `問題点記録書.md` `#0036`
