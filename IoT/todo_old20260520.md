## 020-0015（完了 2026-05-20）

**タスク内容**: `Wi-Fi_lab` USB アダプタによる ESP32 AP 接続の安定化。FW 修正後に `Wi-Fi_lab` で接続できることを検証し、`configureEsp32CloudMode.ps1` の `$AP_IFACE` を `Wi-Fi_lab` に戻す。

**完了内容**:
- Wi-Fi_lab（TP-Link Realtek USB、MAC `78:20:51:45:18:51`）で `AP-esp32lab-04CEF94EB580` への接続成功を確認（`GET http://192.168.4.1/api/health → {"result":"OK","mode":"maintenance-ap"}`）。
- `configureEsp32CloudMode.ps1` の `$AP_IFACE` を `'Wi-Fi'` から `'Wi-Fi_lab'` に変更済み。

**根本原因（2026-05-20 特定）**:
- **主因**: AP Wi-Fi パスワード不一致（`common.h` の `kMaintApPass` がプレースホルダのまま FW に焼かれていた）。PC WLAN プロファイルのパスワードを FW 実値に合わせることで解決。
- **Wi-Fi_lab 固有**: Realtek アダプタが AES-GCMP-128 を選択 → ESP32 IDF 4.4 の GCMP 4-way handshake 失敗。FW の `pairwise_cipher=CCMP` 強制（`main.cpp`）+ Wi-Fi_lab Bandwidth=20MHz Only（`#0034`）で解消。

**証跡**: `問題点記録書.md #0045` / `#0034` / `#0040`

**残課題**: AP Wi-Fi パスワードの FW↔LocalServer 単一ソース化は未着手（`#0040` / `008-0029` 参照）。
