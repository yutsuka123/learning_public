## 2. モジュール詳細

### 2.1 ESP32-S3（フィールドデバイス）

| 項目 | 内容 |
|---|---|
| **言語** | C++17 |
| **ランタイム** | FreeRTOS（ESP-IDF v5.x 内蔵）|
| **ビルド** | PlatformIO（`pio run -e esp32s3_secure`）|
| **ハードウェア** | ESP32-S3 / 240MHz デュアルコア / RAM 520KB / Flash 8MB |
| **役割** | センサーデータ収集・MQTT publish・OTA 受信・コマンド実行 |

**内部モジュール構成:**

```text
ESP32-S3 内部
├── WiFi Driver (esp_wifi.h)
│    └─ STA モード（通常接続）/ AP モード（設定時）
├── MQTT Task (FreeRTOS)
│    ├─ MqttTlsClient.cpp  ← TLS 接続（ローカル / クラウド切替）
│    ├─ mqtt.cpp           ← 接続管理・brokerMode 分岐
│    ├─ mqttProtocol.cpp   ← AES-256-GCM 暗号化 / 復号
│    ├─ mqtt_network.cpp   ← status / notice / alert
│    ├─ mqtt_get.cpp       ← GET コマンド受信
│    ├─ mqtt_set.cpp       ← SET コマンド受信
│    └─ mqtt_call.cpp      ← CALL コマンド受信
├── OTA Task (FreeRTOS)
│    ├─ ota.cpp            ← esp_https_ota / SHA-256 検証 / HMAC 署名検証
│    └─ dual partition     ← app0(0x30000) / app1(0x430000) 交互使用
├── AP Mode Task (FreeRTOS)
│    └─ maintenanceApServer.cpp  ← HTTP Server :80 / 設定 UI
├── Storage
│    ├─ NVS                ← k-device / k-iot / WiFi SSID / Pass
│    └─ LittleFS /certs/   ← X.509 証明書 / sensitiveData.json
└── Security (Hardware + mbedTLS)
     ├─ AES-256-GCM (ハードウェアアクセラレータ使用)
     ├─ SHA-256 (OTA 整合性検証)
     ├─ HMAC-SHA256 (コマンド署名検証)
     ├─ Flash Encryption (AES-XTS・eFuse 管理)
     ├─ Secure Boot v2 (RSA-PSS 署名検証)
     └─ eFuse OTP (不可逆フラグ管理)
```

**接続先切替ロジック:**

```text
NVS: brokerMode = "local" → Mosquitto (172.17.1.100:8883) に接続
                              TLS CA = mqtt-ca.pem (自己署名)
                              認証 = ID/Password
                              WiFi = AP-IoTESP32Test

NVS: brokerMode = "cloud" → AWS IoT Core (<endpoint>:8883) に接続
                              TLS CA = AmazonRootCA1.pem
                              認証 = X.509 mTLS (aws-device-cert.pem + aws-private-key.pem)
                              WiFi = Buffalo-G-41E0 (WAN 接続 AP)
```

### 2.2 AP モード（ESP32 内蔵 SoftAP）

| 項目 | 内容 |
|---|---|
| **起動方法** | BOOT ボタン 3 秒長押し |
| **SSID** | `AP-esp32lab-<MACアドレス>` |
| **パスワード** | `.env` の `AP_WIFI_PASSWORD`（役割別アカウントで管理）|
| **IP** | `192.168.4.1`（固定）|
| **プロトコル** | HTTP :80（設定 UI）|
| **役割** | WiFi SSID/Pass / brokerMode / cloudEndpoint の設定 / 証明書確認 |
| **認証** | role 別（user / maintenance / admin / mfg）/ `.env` で管理 |
| **実装** | `IoT/ESP32/src/maintenanceApServer.cpp` |

**AP モード設定フロー:**
```text
BOOT ボタン長押し
    → ESP32 が SoftAP 起動
    → PC/スマートフォンが AP-esp32lab-XXXX に接続
    → ブラウザで http://192.168.4.1/ を開く
    → brokerMode / WiFi SSID / cloudEndpoint を設定
    → 「保存」→ NVS に書込み → ESP32 再起動
```

| **役割** | MQTT サブスクライバ・REST API・Web UI・OTA 配信・S3 OTA（クラウドモード）|
| **設定** | `IoT/LocalServer/.env`（Git 除外・機密情報含む）|

**モジュール構成:**

```text

├── server.ts          ← Express.js メインサーバー + HTTPS OTA サーバー起動
├── config.ts          ← .env 読込・型付き設定オブジェクト
├── mqttGateway.ts     ← MQTT.js クライアント（ローカル Mosquitto）

├── secretCore.ts      ← Named Pipe IPC（SecretCore との通信）
├── deviceManager.ts   ← デバイス状態管理・オンライン判定
├── localHistoryStore.ts ← SQLite3 履歴保存

└── scripts/
     └── createSensitiveDataJsonForRecovery.cjs ← ESP32 復元用 JSON 生成
```

**AWS 連携（クラウドモード）:**

```text
@aws-sdk/client-s3          → S3 へのファームウェアアップロード
@aws-sdk/s3-request-presigner → Presigned URL 生成（TTL=600s）
mqtt.js (TLS + X.509 mTLS)  → AWS IoT Core への MQTT 接続
  証明書: localserver-cert.pem + localserver-private.key
  CA:     AmazonRootCA1.pem
```

### 2.4 SecretCore

| 項目 | 内容 |
|---|---|
| **言語** | Rust |
| **ビルド** | Cargo（`cargo build`）|
| **実行ファイル** | `IoT/SecretCore/target/release/secret_core.exe` |
| **起動** | LocalServer から自動起動（Named Pipe 接続待ち）|
| **役割** | 秘密情報（k-device・k-user）の保護・導出・暗号化復号 |
| **分離理由** | TypeScript（Node.js）から Rust プロセスを分離し、raw 秘密鍵を HTTP 等で流さない |

**処理フロー:**

```text
LocalServer
    │
    │ Named Pipe IPC: \\.\pipe\local-server-*
    │ JSON リクエスト { "operation": "getKDevice", "publicId": "..." }
    ▼
SecretCore [Rust]
    ├─ wrapped_secret 読込
    │   └─ Windows DPAPI (CryptUnprotectData) で復号 → S_random
    ├─ k-user 導出: HMAC-SHA256(S_random, "k-user")
    ├─ k-device 導出: HMAC-SHA256(k-user, publicId)
    └─ JSON レスポンス { "kDevice": "<base64>" }
    │
    ▼
LocalServer
    └─ AES-256-GCM で MQTT payload を復号
```

### 2.5 ProductionTool

| 項目 | 内容 |
|---|---|
| **言語** | Rust |
| **ビルド** | Cargo |
| **役割** | 製造工程の段階実行ランナー。ESP32 への鍵書込み・セキュア化を安全に行う |
| **使用外部ツール** | `esptool.py`（フラッシュ書込み）/ `espefuse.py`（eFuse 書込み）|
| **実行制約** | `productionTool` 経由以外での `espefuse.py` 直接実行は**禁止**（不可逆操作のため）|

**製造工程の段階:**

```text
Stage 1: 事前確認
    ├─ ESP32 チップ情報確認 (chip_id / mac / flash_size)
    └─ eFuse 状態確認（書込み済みか確認）

Stage 2: ファームウェア書込み
    └─ esptool.py write_flash firmware.bin

Stage 3: k-iot 鍵書込み
    └─ カスタム NVS 書込み（k-iot-secure-boot / k-iot-flash-encryption）

Stage 4: Flash Encryption 有効化
    └─ espefuse.py burn_efuse SPI_BOOT_CRYPT_CNT（不可逆）

Stage 5: Secure Boot v2 署名鍵書込み
    └─ espefuse.py burn_key BLOCK_KEY0 ... (不可逆)

Stage 6: セキュリティフラグ封鎖
    └─ espefuse.py burn_efuse DIS_DOWNLOAD_ICACHE / JTAG_DISABLE 等（不可逆）

★ 各 Stage でゲートチェック（前提条件を満たさない限り次に進めない）
```

### 2.7 AWS IoT Core（クラウド MQTT ブローカー）

| 項目 | 内容 |
|---|---|
| **サービス** | AWS IoT Core（フルマネージド）|
| **リージョン** | `ap-northeast-1`（東京）|
| **ポート** | 8883（TLS）|
| **エンドポイント** | `<prefix>-ats.iot.ap-northeast-1.amazonaws.com`（アカウント固定）|
| **認証** | X.509 mTLS（相互認証）+ Amazon Root CA 1 |
| **認可** | IoT Policy（JSON 形式・Connect/Publish/Subscribe/Receive をトピック単位で制御）|
| **役割** | クラウドモード時の MQTT ブローカー。ESP32 と LocalServer の通信ハブ |

**IoT Policy 構造（LocalServer 用）:**

```json
{
  "Statement": [
    { "Action": "iot:Connect",
      "Resource": "*/client/localserver-*" },
    { "Action": ["iot:Subscribe", "iot:Receive"],
      "Resource": ["*/topic/esp32lab/*", "*/topicfilter/esp32lab/*"] },
    { "Action": "iot:Publish",
      "Resource": "*/topic/esp32lab/*" }
  ]
}
```

**IoT Policy 構造（ESP32 用）:**

```json
{
  "Statement": [
    { "Action": "iot:Connect",
      "Resource": "*/client/IoT_*" },
    { "Action": ["iot:Publish", "iot:Subscribe", "iot:Receive"],
      "Resource": ["*/topic/esp32lab/*", "*/topicfilter/esp32lab/*"] }
  ]
}
```

## 3. MQTT トピック構造

```text
esp32lab / <kind> / <sub> / <deviceName>
           │         │        │
           │         │        └─ デバイス識別子（例: IoT_04CEF94EB580）
           │         └─ サブカテゴリ
           └─ kind: notice / get / set / call / alert / ota

主要トピック一覧:
─────────────────────────────────────────────────────────────────
 ESP32 → ブローカー (Publish)
  esp32lab/notice/status/<name>      デバイス状態通知（オンライン/オフライン）
  esp32lab/notice/trh/<name>         温湿度気圧データ
  esp32lab/notice/alert/<name>       アラート通知
  esp32lab/notice/ota/<name>         OTA 進捗通知

 ブローカー → ESP32 (Subscribe / Receive)
  esp32lab/call/<cmd>/<name>         コマンド実行要求（LED/リレー/再起動）
  esp32lab/set/<item>/<name>         設定変更（WiFi/証明書）
  esp32lab/get/<item>/<name>         データ取得要求
  esp32lab/ota/start/<name>          OTA 開始コマンド

 ESP32 → ブローカー → LocalServer
  すべて AES-256-GCM 暗号化済み payload として流れる
  平文: { "onlineState": "Online", "wifiSsid": "...", ... }
  送信: Base64(nonce + ciphertext + tag)
─────────────────────────────────────────────────────────────────
```

### 4.7 暗号化・鍵管理フロー

```text
鍵階層と暗号化フロー

═══ 鍵の生成・保護（LocalServer 側）════════════════════════════════

 Windows DPAPI
    │ CryptProtectData (ユーザー認証情報でラップ)
    ▼
 wrapped_secret.bin (ファイル保存)
    │ CryptUnprotectData → S_random (32 byte)
    ▼
 k-user = HMAC-SHA256 (key=S_random, message="k-user")
    │
    ├── k-device_A = HMAC-SHA256 (key=k-user, message=publicId_A)
    ├── k-device_B = HMAC-SHA256 (key=k-user, message=publicId_B)
    └── k-device_C = HMAC-SHA256 (key=k-user, message=publicId_C)

★ デバイスごとに固有の k-device → 1台漏洩しても他のデバイスには無影響

═══ MQTT payload 暗号化フロー（ESP32 側）═════════════════════════════

 ESP32 が送信時:
   plaintext = { "onlineState": "Online", "wifiSsid": "..." }
   nonce = 12 byte random（毎回再生成）
   ciphertext, tag = AES-256-GCM.Encrypt(key=k-device, nonce, plaintext)
   送信: Base64(nonce || ciphertext || tag)

 LocalServer が受信時:
   受信: Base64 encoded データ
   nonce, ciphertext, tag = decode(data)
   k-device を SecretCore から取得 (IPC)
   plaintext = AES-256-GCM.Decrypt(key=k-device, nonce, ciphertext, tag)
   tag 不一致 → エラー（改ざん検知）

═══ OTA コマンド署名フロー ════════════════════════════════════════════

 LocalServer が OTA コマンド送信時:
   command = { "url": "...", "sha256": "...", "version": "..." }
   signature = HMAC-SHA256 (key=k-user, message=JSON(command))
   payload = AES-256-GCM.Encrypt (key=k-device, command + signature)
   送信

 ESP32 が受信時:
   AES-256-GCM 復号
   HMAC-SHA256 署名検証 (key=k-device)
   SHA-256 ファームウェア整合性検証
   フラッシュ書込み
```

### 5.1 防御レイヤー

```text
攻撃面と対策

─────────────────────────────────────────────────────────────
 攻撃面              脅威                    対策
─────────────────────────────────────────────────────────────
 通信路              盗聴                    TLS 1.2（通信路暗号化）
 通信路              MITM                    X.509 証明書認証
 MQTT payload       盗聴                    AES-256-GCM（二重暗号化）
 MQTT payload       改ざん                   GCM tag 検証 / HMAC 署名
 OTA バイナリ        改ざん                   SHA-256 整合性検証
 OTA コマンド        なりすまし               HMAC-SHA256 署名検証
 デバイス物理盗難     フラッシュ解析           Flash Encryption (AES-XTS)
 デバイス物理盗難     改造 FW 書込み           Secure Boot v2 (RSA-PSS 検証)
 eFuse 書込み後      設定変更                 eFuse 不可逆封鎖
 PC 複製            LocalServer 複製         Windows DPAPI (別 PC で復号不可)
 IPC 傍受           k-device 横取り          Named Pipe (OS 保護)
 コード解析          k-device 逆算           k-user なしでは導出不可
 証明書              秘密鍵盗難              リポジトリ外保管 + .gitignore
─────────────────────────────────────────────────────────────
```
