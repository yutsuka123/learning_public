## 2. 実機復旧と確認結果
- 対象機: `IoT_04CEF94EB580`
- 症状:
  - LCD が `MQTT RECONNECT` を繰り返した。
  - Mosquitto ログに `OpenSSL ... unexpected eof while reading` / `protocol error` が出ていた。
- 確認:
  - Mosquitto 設定、認証ファイル、証明書は今回変更していない。
  - LocalServer 側は `mqtts://172.17.1.100:8883` へ接続できたため、Broker 側ではなく ESP32 側を優先調査した。
- 対策:
  - `ESP32/src/sensitiveData.cpp` と `ESP32/src/main.cpp` に、`mqttPort=8883` の場合は `mqttTls=true` を強制する補正を追加した。
  - 平文接続へ落とす対応は行わず、`8883/TLS` の正規要件へ合わせた。
  - TLS補正後に残った `k-device` 欠落は、SecretCore 現行値を raw 表示せず fingerprint `2445cc99fcc4c4e7` / decoded length 32 byte のみ確認し、LittleFS 経由で NVS へ復元した。
- 結果:
  - シリアルで `Certificate verified`、`connectToMqttBroker success`、LCD `MQTT CONN`、`publishStatusNotice success` を確認した。
  - `GET /api/admin/devices` で `onlineState=online` / `ipAddress=172.17.1.200` を確認した。
  - `7044` E2E は `[OK] fileSync image update completed`、`files=1`、`totalChunks=1`、`phase=completed`、`detail=commit completed` で成功した。

## 3. PlatformIO upload offset 再発防止
- 問題:
  - PlatformIO 標準 upload が旧 factory 相当の `0x10000` に書くと、現行 partition `app0=0x30000` と不整合になる。
- 対策:
  - `IoT/ESP32/platformio.ini` の全 ESP32 env に `board_upload.offset_address=0x30000` を明示した。
  - `IoT/ESP32/scripts/ensure_app0_upload_offset.py` を追加し、`0x30000` 以外なら PlatformIO 実行を停止するようにした。
- 確認:
  - `python -m platformio run -e esp32s3_secure` は成功。
  - `envdump` で `esp32s3_secure` / `esp32s3_secure_final` / `esp32s3_secure_rescue` の `ESP32_APP_OFFSET=0x30000` を確認済み。
