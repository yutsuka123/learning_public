## 2. アーキテクチャ決定：ESP32 直接接続方式（Option B 確定）

[重要] 当初 LocalServer MQTT Bridge 方式（Option A）を検討したが、  
**ESP32 が直接 AWS IoT Core に接続する Option B に確定**（2026-05-20）。  
理由: AWS IoT Core 本来の設計（デバイス直接接続）に合致し、LocalServer を中継ルータにしない方がシンプルで安全。

### 2.1 採用アーキテクチャ

```text
═══════════════════════════════════════════════════════════════════════════
  [クラウドモード（CLOUD_MQTT_ENABLED=true）]
═══════════════════════════════════════════════════════════════════════════

  ESP32-S3                 AWS IoT Core（東京リージョン ap-northeast-1）
    │                        ┌──────────────────────────────────────────┐
    │  TLS 8883              │  MQTT Broker                             │
    │  X.509（device cert）   │  ・IoT Policy（topic 単位の認可）        │
    │  AES-256-GCM payload   │  ・TLS 8883 mutual auth                 │
    └──────────────────────►│  ・IoT Rules Engine → Lambda（任意）     │
                             │                                          │
  LocalServer（Node.js）     │                                          │
    │  TLS 8883              │                                          │
    │  X.509（server cert）  │                                          │
    └──────────────────────►│  ← subscribe（受信）                     │
                             └──────────────────────────────────────────┘

  SecretCore（Rust）← 変更なし（k-device 導出・payload 復号は LocalServer ローカルで完結）

═══════════════════════════════════════════════════════════════════════════
  [ローカルモード（CLOUD_MQTT_ENABLED=false、またはフォールバック時）]
═══════════════════════════════════════════════════════════════════════════

  ESP32-S3                 Mosquitto（172.17.1.100:8883）
    │  TLS 8883              │
    │  ID/Password           │
    │  AES-256-GCM payload   │
    └──────────────────────►│
                             │
  LocalServer（Node.js）    │
    └──────────────────────►│  ← subscribe（既存動作・変更なし）

═══════════════════════════════════════════════════════════════════════════
  モード切替: ESP32 NVS フラグ brokerMode=local|cloud（AP モード設定 UI）
             LocalServer .env CLOUD_MQTT_ENABLED=true|false
═══════════════════════════════════════════════════════════════════════════
```

### 2.2 ESP32 側：クラウドモード追加（X.509 証明書導入）

- **NVS フラグ `brokerMode`** で接続先を切替:
  - `brokerMode=local`（デフォルト）: `mqtt.esplab.home.arpa:8883`（TLS + ID/Password）
  - `brokerMode=cloud`: `<endpoint>.iot.ap-northeast-1.amazonaws.com:8883`（TLS + X.509）
- **モード切替方法**: ESP32 を AP モードにして Web 設定 UI から `brokerMode` を書換え → 再起動
- **X.509 証明書の配備先**（クラウドモード時）:
  - LittleFS `/certs/aws-device-cert.pem`（AWS IoT Core 発行デバイス証明書）
  - LittleFS `/certs/aws-private-key.pem`（秘密鍵）
  - LittleFS `/certs/AmazonRootCA1.pem`（Amazon Root CA）
  - 証明書の書込みは OTA or 専用 Web API エンドポイント経由（実装は `012-0005` 以降）
- **AES-256-GCM payload 暗号化（k-device）は両モードで不変**
- `clientId` はクラウドモードでも `publicId`（`esp32s3-<hex>`）を使用

### 2.3 LocalServer 側：クラウド subscriber モード追加

- `CLOUD_MQTT_ENABLED=true` 時: AWS IoT Core に subscribe し、クラウド経由 MQTT メッセージを受信
- AWS IoT Core への接続認証は **X.509 クライアント証明書**（LocalServer 用 device cert）
- 証明書ファイルパスは `IoT/LocalServer/.env`（Git 除外）に記載（§5.6 参照）
- LocalServer → AWS IoT Core の接続は `aws-iot-device-sdk-v2`（Node.js）を使用
- `CLOUD_MQTT_ENABLED=false` 時: Mosquitto のみ subscribe（既存動作・変更なし）
- **LocalServer は Mosquitto への subscribe を常に維持**（クラウド ON でも Mosquitto は継続）

### 2.4 クラウド側設定

| 項目 | ESP32（device） | LocalServer（server） |
|---|---|---|
| リージョン | ap-northeast-1（東京）| ap-northeast-1（東京）|
| Broker エンドポイント | AWS IoT Core custom endpoint（AWS コンソールで取得）| 同左 |
| 接続ポート | TLS 8883 | TLS 8883 |
| デバイス認証 | X.509 クライアント証明書（ESP32 用）| X.509 クライアント証明書（LocalServer 用）|
| clientId | `publicId`（`esp32s3-<hex>`）| `localserver-<hostname>` |
| Topic 設計 | 現行の `esp32lab/<kind>/<sub>/<name>` をそのまま使用 | 同左 |
| IoT Policy | `Connect/Publish/Subscribe/Receive`（topic 単位）| `Connect/Subscribe/Receive`（+ Publish はコマンド送信時）|
| IoT Rules | 必要に応じて topic フィルタ → Lambda 実行 | 同左 |

### 2.5 Cognito の役割

| 用途 | 採用可否 | 理由 |
|---|---|---|
| ESP32 / LocalServer → AWS IoT Core 接続 | **X.509 を採用**（不要）| デバイス・サーバー間は X.509 が標準。Cognito は Web/Mobile ユーザー向け |
| Web ダッシュボードからの MQTT subscribe | 将来候補 | Cognito Identity Pool → WebSocket over MQTT の経路で実現可能 |
| Lambda からの処理認証 | IAM Role を使用 | Lambda は IAM Role で AWS IoT Core にアクセス |

### 2.6 Lambda の役割

| 用途 | 採用タイミング |
|---|---|
| IoT Rules による topic → DynamoDB / S3 書込み | 必要に応じて `012-0005` 以降 |
| Custom Authorizer（username/password → IoT Policy）| 不要（ESP32・LocalServer ともに X.509）|
| データ変換・フィルタリング | 必要に応じて追加 |

## 3. Broker 候補比較（012-0001 / 012-0002 の結論）

### 3.1 AWS vs Google 比較（012-0002 結論）

| 比較項目 | AWS IoT Core | Google Cloud IoT Core |
|---|---|---|
| **現状** | サービス継続中 | **2023-08-16 サービス終了済み** |
| **代替** | ─ | Google Cloud MQTT bridge → Pub/Sub |
| **採用可否** | **採用** | **不採用（廃止済み）** |

→ **AWS IoT Core のみが候補** となる（Google Cloud IoT Core は廃止済みのため）。

### 3.2 MQTT Broker 候補比較（012-0001 結論）

| 比較項目 | AWS IoT Core | EMQX Cloud | HiveMQ Cloud |
|---|---|---|---|
| **日本リージョン** | ✅ ap-northeast-1（東京）| ✅ あり | ❌ なし（最寄: シンガポール）|
| **コスト** | 従量課金（接続 + メッセージ課金）、試験時は無料枠 | 従量課金 / Serverless あり | 無料枠あり・有料プランから |
| **無料枠** | ✅ 12ヶ月 500K msg/月 | ✅ Serverless 無料枠あり | ✅ 無料プランあり（接続数制限）|
| **X.509 認証** | ✅ ネイティブ対応 | ✅ 対応 | ✅ 対応 |
| **ID/Password 認証** | ❌ 非対応（Custom Auth Lambda が必要）| ✅ 対応 | ✅ 対応 |
| **Cognito 連携** | ✅ ネイティブ（Identity Pool）| ❌ 非対応 | ❌ 非対応 |
| **Lambda 連携（IoT Rules）** | ✅ ネイティブ（IoT Rules Engine）| ❌ 非対応 | ❌ 非対応 |
| **Mosquitto Bridge 対応** | ✅ 対応 | ✅ 対応 | ✅ 対応 |
| **AWS エコシステム統合** | ✅ DynamoDB / S3 / CloudWatch 直結 | △ 別途 API 連携 | △ 別途 API 連携 |
| **マネージド度** | ✅ フルマネージド | ✅ フルマネージド | ✅ フルマネージド |
| **無難さ** | **最高**（AWS 公式サービス、実績豊富）| 中程度（OSS ベース）| 中程度 |

→ **AWS IoT Core を採用**。理由:
1. 日本リージョンあり（低レイテンシ）
2. Cognito / Lambda との**ネイティブ統合**がユーザー要件に合致
3. **フルマネージド**で運用負荷ゼロ
4. IoT Rules Engine による **Lambda 連携**が容易
5. 無料枠（12ヶ月）で**試験時コストを抑制**可能
6. **無難な選択**（AWS 公式・実績豊富・廃止リスクなし）

## 4. フォールバック設計（Cloud → Local 切替方法）

| 対象 | 切替手順 | 所要時間 |
|---|---|---|
| **ESP32 のみ** | AP モード起動 → Web 設定 UI で `brokerMode=local` に変更 → 再起動 | 約 1〜2 分 |
| **LocalServer のみ** | `LocalServer/.env` の `CLOUD_MQTT_ENABLED=false` に変更 → 再起動 | 約 30 秒 |
| **完全ローカル復帰** | 上記両方を実施 | 約 2 分 |
| **データ継続性** | ローカル SQLite 履歴はクラウドと独立して維持 | ─ |
| **証明書の扱い** | LittleFS の証明書は削除不要。ローカルモードでは参照されない | ─ |

[注意] ESP32 がクラウドモードのまま LocalServer だけをローカルに戻すと、  
ESP32 → AWS IoT Core へのメッセージが LocalServer に届かなくなる。  
フォールバック時は **ESP32 と LocalServer を同時に切り替える**こと。

| 現行実装 | クラウド拡張後 | 変更有無 |

| SecretCore 鍵管理 | **変更なし** | ✅ 不変 |

## 6. 次のステップ（012-0005 / 009-0004 への引き渡し）

`012-0001` / `012-0002` / `012-0004` 完了を受けて、次は `012-0005` / `009-0004`（LocalServer クラウド連携 I/F 設計）へ着手できる。

実装時の具体的な手順は `クラウド構築手順書.md` に記載。概要:

**【AWS 側準備】**
1. AWS IoT Core エンドポイント取得（AWS コンソール or CLI）
2. ESP32 用 X.509 device cert 発行（AWS IoT コンソール or CLI）
3. LocalServer 用 X.509 device cert 発行（別途）
4. ESP32 用 IoT Policy 作成（`esp32lab/#` の `Connect/Publish/Subscribe/Receive`）
5. LocalServer 用 IoT Policy 作成（`esp32lab/#` の `Connect/Subscribe/Receive`）

**【ESP32 側準備】**
6. AWS 発行の証明書を ESP32 LittleFS `/certs/` に書込み（Web API or OTA）
7. NVS `brokerMode=cloud` / `cloudEndpoint=<endpoint>` を書込み（AP モード設定 UI）

**【LocalServer 側準備】**
8. `LocalServer/.env` に `CLOUD_MQTT_ENABLED` / `AWS_IOT_ENDPOINT` / 証明書パスを追加
9. LocalServer に AWS IoT Core subscriber 機能実装（`aws-iot-device-sdk-v2` for Node.js）

**【試験】**
10. ESP32 クラウドモード起動 → AWS IoT Core で受信確認
11. LocalServer クラウドモード起動 → LocalServer が AWS IoT Core subscribe 受信確認
12. フォールバック試験: `brokerMode=local` に戻してローカル通信確認

詳細手順書: `IoT/クラウド構築手順書.md`（2026-05-20 新設）
