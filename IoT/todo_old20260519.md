## 009-0012: サーバ側 k-device 導出処理（既実装確認＋仕様の HKDF → HMAC 整合）

- [完了][2026-05-19] [009-0012] サーバ側で `k-device` 導出処理を実装する。
  - [完了理由][2026-05-19] 当該機能は **`SecretCore/src/key_manager.rs:454-465 get_k_device()`** で実装済みであることを確認した。
    - 導出式: `HMAC-SHA256(key=k_user, message=target_device_name)`（`target_device_name` = `publicId`、初期値 `IoT_<base MAC からコロン除去>`）
    - 出力: 32 byte（HMAC-SHA256 のダイジェスト長そのもの）
    - 利用箇所: `sign_by_k_device`（command 署名）／`encrypt_by_k_device` / `decrypt_by_k_device`（AES-256-GCM 鍵）／`ota_workflow.rs:344`（OTA 開始署名）／`mqtt_transport.rs:921`（受信 payload 復号）
    - IPC 公開 API: `main.rs:352 "get_k_device"` で base64 形式での取得経路あり
  - [仕様正本] 設計仕様書群を 2026-05-19 に **HKDF → HMAC** で正本更新（実装は HMAC-SHA256 直接導出のまま）：
    - `鍵管理および初期セットアップ設計仕様書.md` §3 鍵構造 / §6.1 device_id / §6.2 生成式 / §6.3 設計意図 / §16 変更履歴
    - `LocalServer秘密処理別層仕様書.md` §3.1 鍵構造 / §13 変更履歴
    - `IF仕様書.md`（k-device 生成式）/ `WiFi設定更新_詳細設計書.md`（鍵設計）/ `セキュリティ方針_認証情報取扱い.md`（k-device 生成）/ `要件定義書.md` FR-009 / `鍵一覧仕様書.md`（k-device 行）/ `鍵管理初期セットアップ_実装たたき台.md`（Phase2 現状）
  - [変更理由] HKDF と HMAC-SHA256 直接導出の事実上の安全性差は無い（HKDF も内部で HMAC-SHA256 を 2 段使う）。command 署名（`sign_by_k_device`）／OTA 開始署名（`ota_workflow.rs:344`）／ESP32 側 `mbedtls_md_*`（`secureNvsInit.cpp` / `MQTT/mqtt.cpp`）も HMAC-SHA256 で統一されており、`k-device` 導出だけ HKDF にすると実装・試験が分岐するだけで利点がないため、実装側へ寄せる。
  - [後続対応] なし。
