# 耐量子暗号移行計画書

[重要] 本書は、2030年以降に想定する post-quantum cryptography（耐量子暗号、PQC）移行の方針を定義する。  
理由: 現行の ESP32 / LocalServer / SecretCore / ProductionTool は、直近の第3段階・第4段階完了を優先しており、PQC を今すぐ実装へ混ぜると検証範囲が過大化するため。

## 1. 目的
- [重要] 2030年以降に、量子計算機による既存公開鍵暗号への影響を再評価し、必要に応じて鍵交換・署名方式を耐量子暗号へ移行する。
- [厳守] 本計画は将来対応であり、現行の OTA、pairing、SecretCore、ProductionTool の完了条件へ追加しない。
- [推奨] 2028年以降、NIST / IPA / JPCERT / ESP-IDF / OpenSSL / RustCrypto などの対応状況を年1回確認する。

## 2. 対象範囲
- [重要] 対象は、OTA 署名、pairing 時の鍵交換、LocalServer と SecretCore の IPC 保護、将来 CloudServer とデバイス間の認証である。
- [重要] 現行の `k-user` / `k-device` / HMAC / AES-256-GCM は、当面は対称鍵系として継続利用する。
- [将来対応] 公開鍵系の置換候補として、鍵共有は ML-KEM、署名は ML-DSA または SLH-DSA を優先候補として追跡する。
- [補足] 旧称 CRYSTALS-Kyber は、標準化後の名称では ML-KEM として扱う。

## 3. 移行候補
| 用途 | 現行または想定方式 | 将来候補 | 備考 |
| :--- | :--- | :--- | :--- |
| pairing 鍵交換 | ECDH / セッション鍵導出 | ML-KEM または hybrid ECDH + ML-KEM | ESP32 側 ROM / RAM / パケットサイズを要実測 |
| OTA 署名 | 既存署名 / HMAC 併用 | ML-DSA または SLH-DSA | 署名サイズ増大と検証時間を評価 |
| SecretCore IPC | DH + AES-GCM | hybrid DH + ML-KEM | ローカル IPC は優先度低。外部公開面より後で評価 |
| Cloud 連携 | X.509 / MQTT TLS | TLS ライブラリの PQC 対応待ち | Cloud 第4段階の責務分界と同時評価 |

## 4. 移行判定条件
- [厳守] 標準化直後のアルゴリズムを独自実装して本番投入しない。理由: 実装バグ、サイドチャネル、相互運用性不足のリスクが高いため。
- [厳守] ESP32 側で、ROM 使用量、RAM 使用量、処理時間、MQTT / HTTPS ペイロード増大を実測してから採用可否を判断する。
- [厳守] 既存の AES-256-GCM、HMAC、nonce、timestamp、keyVersion の検証を削らない。
- [推奨] 当面は hybrid 方式を優先検討する。理由: 既存方式と PQC の片方に問題があっても、もう片方で防御余地を残せるため。

## 5. 2030年以降の作業案
1. [将来対応] 2030年時点の NIST / 各ライブラリ / ESP-IDF の対応状況を確認する。
2. [将来対応] `012` 章の Cloud 連携設計と合わせ、証明書・署名・鍵交換の責務分界を再評価する。
3. [将来対応] ESP32 実機で ML-KEM / ML-DSA / SLH-DSA のサイズ・速度・メモリ消費を比較する。
4. [将来対応] OTA 署名から先に PoC し、pairing と IPC は後続評価にする。
5. [将来対応] 移行試験番号を `8000` 番台または当時の試験体系で新規採番する。

## 6. 禁止事項
- [禁止] 現行タスクを早く閉じるために、未検証の PQC ライブラリを本番経路へ混ぜない。
- [禁止] 署名サイズ増大を理由に、署名検証や HMAC 検証を省略しない。
- [禁止] PQC へ移行したことだけを根拠に、TLS、nonce、timestamp、監査ログを弱めない。
- [新規利用禁止] 独自暗号、独自パディング、独自 KEM を新規採用しない。
