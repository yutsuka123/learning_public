### SecretCore `key_protect.rs` デュアルモード実装

- **実装概要**: `SecretCore/src/key_protect.rs` を新規設計し、ファイルベース AES-256-GCM と Windows DPAPI を環境変数 `PROTECT_MODE` で切替可能にした。
- **ファイルベース AES-256-GCM モード（デフォルト）**:
  - 32 byte CSPRNG wrapping key を `LocalServer/data/keys/master_key.bin` に保存
  - `wrapped_secret.bin` = 280 bytes（形式: `[12 byte nonce][ciphertext][16 byte GCM tag]`）
  - OS パーミッション: `data/keys/` ディレクトリ = Full(User+SYSTEM), Delete(Admins); ファイル = 同様
- **Windows DPAPI モード**（`PROTECT_MODE=dpapi`）:
  - `CryptProtectData` / `CryptUnprotectData` をユーザースコープで使用
  - `wrapped_secret.bin` = 552 bytes（DPAPI 出力サイズ）
  - `master_key.bin` は使用しない
  - `.env` に `PROTECT_MODE=dpapi` を追加すると有効化
- **Cargo.toml 追加依存**: `winapi = { version = "0.3", features = ["dpapi", "wincrypt", "winbase"] }`（Windows のみ）

### 020-0016（NVS 消失原因究明）— 完了退避

- [x] [020-0016] [2026-05-20→完了 2026-05-23][緊急→完了][重要] **NVS 消失原因究明**（`012-0008` 試験中に k-device が NVS から消失した根本原因を調査し、再発防止策を講じる）

  - [原因特定][2026-05-20] **`IoT/ESP32/src/secureNvsInit.cpp` の `nvs_flash_erase()` が根本原因**。
    - `fallbackPlaintextNvsInit()`（secureNvsInit.cpp:141-146）と `initializeSecureNvs()`（secureNvsInit.cpp:279-291）の両方に、`nvs_flash_init()` が `ESP_ERR_NVS_NO_FREE_PAGES` / `ESP_ERR_NVS_NEW_VERSION_FOUND` を返した場合に `nvs_flash_erase()`（NVS 全消去）を呼ぶコードがあった。
    - `ESP_ERR_NVS_NEW_VERSION_FOUND` は開発中にファームウェアのビルド設定（ESP-IDF バージョン、NVS スキーマ）が変わった場合に発生し、USB フラッシュ・OTA のいずれのリブート後にも起きうる。
    - フラッシュ操作自体（USB・OTA）は NVS パーティションを触らない。問題はリブート後の起動シーケンスで `nvs_flash_erase()` が呼ばれること。
    - 安定した製品運用（同一 ESP-IDF・同一 NVS スキーマ）では通常発生しない。開発中が高リスク期間。
  - [短期対処][2026-05-20] `IoT/LocalServer/scripts/createSensitiveDataJsonForRecovery.cjs` に `cloud` 引数対応を追加。NVS 消去後の LittleFS 回復 JSON に `mqtt.brokerMode=cloud` + `mqtt.cloudEndpoint` も含めることで、次回リブート時に k-device と brokerMode を同時復元できる。根本修正は `020-0017`。
  - [完了証跡][2026-05-23]
    - 根本原因: `secureNvsInit.cpp` の `nvs_flash_erase()` 自動呼び出し（`020-0017` で修正済み）
    - 012-0008 全件クリア（7200〜7209 PASS）・dual-partition OTA PASS で k-device 保持確認
