# IoT システム構成と通信フロー（初心者向け統合ガイド）

[重要] 本書は **IoT プロジェクト全体の構成と通信フローを初心者にも分かるように説明する** ことを目的とする。  
理由: 既存の `設計概要.md` / `モジュール仕様書.md` / `ネットワーク運用仕様書.md` などは上位設計や責務定義に重点があり、「**そもそも何がどう繋がっているのか**」を一度に把握できる入口文書が不足していたため。

[厳守] 本書は **概要と相互参照を中心とする**。各モジュールの詳細仕様は **「## 99. 関連文書」** の各文書を正本とする。  
理由: 詳細を本書内に書き写すと正本との二重保守が発生し、整合性を保てなくなるため。

[厳守] 機密情報（実際のパスワード・raw 鍵値・eFuse 実値・証明書秘密鍵）は本書に **記載しない**。  
理由: 公開リポジトリ運用のため、漏洩したら被害が大きい情報は本書では「役割」と「保存場所の種類」のみを示し、実値は別の安全領域で管理する。

## 1. このシステムで何ができるか（30 秒で理解）

このシステムは、**ESP32-S3 マイコン**（IoT デバイス）と **PC 上のローカルサーバー**（LocalServer）を **MQTT** という軽量メッセージ通信でつなぎ、以下を実現する。

- **デバイス状態の監視**: 温度・湿度・気圧・LED 状態・GPIO 入出力など
- **デバイスへの指令**: LED 点灯・リレー切替・GPIO 制御・再起動・メンテナンスモード遷移
- **遠隔ファームウェア更新（OTA）**: ESP32 のソフトウェアを HTTPS 経由で書き換え
- **設定変更**: Wi-Fi / MQTT 接続先 / 認証情報を遠隔から更新
- **セキュア化**: 製造工程で **Flash Encryption** / **Secure Boot v2** / **eFuse 封鎖** を行い、量産時の改ざんとコピーを防ぐ
- **障害復旧**: 物理ボタン長押しで **AP モード** に遷移し、PC から Wi-Fi で接続して現地復旧

[重要] 通常運用は **「PC 1 台 + ESP32 デバイス複数」** がローカルネットワーク内で動く構成。クラウドは将来対応（`012` 章）。  
理由: 第 3 段階では **オンプレ独立** を前提とし、別 PC へのコード複製や認証情報抜き取りに対する防御を、ローカル内で完結させる設計とした。

## 3. 各モジュールの役割と機能

### 3.1 ESP32-S3（デバイス側ファームウェア）

| 項目 | 内容 |
|---|---|
| **役割** | センサー値の収集と通知、サーバからの指令の実行、Wi-Fi/MQTT 設定の永続化、OTA でのファームウェア更新、現地復旧用 AP モード提供 |
| **実装言語** | C/C++（C++20 推奨）/ PlatformIO + Arduino-ESP32 |
| **チップ** | ESP32-S3（16MB Flash、Dual core Xtensa LX7） |
| **主要技術** | FreeRTOS（タスク並行）、mbedtls（TLS / AES-256-GCM / HMAC）、ESP-IDF NVS、LittleFS、`esp_ota_*` API（A/B partition + rollback）、`espefuse`（eFuse 操作） |
| **保存先** | **NVS**: 機密性のある運用設定（Wi-Fi/MQTT/HTTPS/時刻同期/`k-device`）／ **LittleFS**: 大容量・更新頻度高めの非機密データ（画像 `/images`、証明書 `/certs`、ログ `/logs`） |
| **依存モジュール** | Mosquitto（MQTT 通信）／ LocalServer（HTTPS OTA 配布元・AP モード時の対向 PC） |

**機能一覧（主要なもの）**

- **MQTT 通信**：`esp32lab/<kind>/<sub>/<name>` 体系で publish/subscribe（kind = `notice` / `set` / `get` / `call` / `network` / `status`）。詳細は `MQTTコマンド仕様書.md` §2.1
- **HTTPS OTA**：LocalServer からの manifest を取得し、SHA-256 + 署名検証付きで firmware を `app1` partition へ書込み、再起動して動作確認後に `otadata` 切替（dual app partition）
- **OTA Rollback**：起動失敗時に旧 partition へ自動復帰（`BOOTLOADER_APP_ROLLBACK_ENABLE`、`otaRollback.cpp`）。**旧称「Dual バンク」と呼ばれていた機構**
- **AP モード**：起動時ボタン 3 秒長押し で `AP-esp32lab-<MAC>` を起動、`192.168.4.1` で Web UI 提供（4 ロール認証：user/maintenance/admin/mfg）
- **k-device による暗号通信**：MQTT payload を AES-256-GCM で暗号化、HMAC-SHA256 で署名（OTA 開始・重要設定変更など高リスク command）
- **時刻同期**：NTP で時刻取得、ログのタイムスタンプに使用
- **物理 I/O**：BME280（温湿度気圧）、LED、リレー、GPIO、ボタン入力
- **ファイルログ**：シリアルとは別経路、30 日 or 100KB で古い順削除、時刻同期前は起動回数パスへ保存

**実装場所**：[`IoT/ESP32/src/`](IoT/ESP32/src/) 配下。主要ファイルは `main.cpp` / `wifi.cpp` / `MQTT/mqtt.cpp` / `httpProtocol.cpp` / `ota.cpp` / `otaRollback.cpp` / `maintenanceApServer.cpp` / `secureNvsInit.cpp` / `sensitiveData.cpp` / `filesystem.cpp` 等

### 3.2 LocalServer（PC 側 TypeScript / Node.js 本体）

| 項目 | 内容 |
|---|---|
| **役割** | 通常運用の UI（Web）と REST API、デバイス一覧・状態表示、OTA 配布、SQLite 履歴保存、運用設定の管理、AP メンテナンス一括処理 |
| **実装言語** | TypeScript / Node.js（v22 系、`better-sqlite3` ネイティブモジュール対応） |
| **対応 OS** | 現行：Windows 11（DPAPI 使用のため）／ Mac/Linux 汎用化は `020-0004` で対応 |
| **主要技術** | Express（REST + WebSocket）、`mqtt`（MQTT.js）、`better-sqlite3`（履歴 DB）、Node `crypto`（IPC 保護用 AES-256-GCM）、PowerShell 起動スクリプト + Windows Task Scheduler 自動起動 |
| **ポート** | 3100（HTTP Web UI + REST）／ 4443（HTTPS OTA 配布） |
| **依存モジュール** | Mosquitto（MQTT publish/subscribe）／ SecretCore（鍵管理・署名・暗号化を IPC で依頼）／ ブラウザ（Web UI）／ ProductionTool（共通の共通部を再利用） |

**機能一覧（主要なもの）**

- **Web UI（ブラウザ）**：デバイス一覧（`admin.html`）、設定（`settings.html`）、ペアリング進捗、OTA 操作、SQLite 履歴
- **REST API**：`/api/devices/...`（デバイス一覧・状態）、`/api/workflows/{pairing|key-rotation|production|signed-ota}/start` + `GET /api/workflows/{workflowId}`（高リスクワークフロー）、`/api/admin/...`（管理系）、`/api/health`（生存確認）
- **WebSocket**：デバイス状態のリアルタイム配信
- **MQTT 中継**：ESP32 からの notice 受信 → DTO 正規化 → SQLite 保存 → UI 配信。command publish は SecretCore 経由で署名 + 暗号化
- **HTTPS OTA 配布**：4443 で manifest と firmware.bin を配布、SHA-256 / 署名検証はメーカー署名前提
- **SQLite 履歴保存**：`commandHistory` / `deviceStatusHistory` / `lastSeenAt` 等、保存期間は `localHistoryRetentionDays`（30 / 90 / 365 / 0=無期限）
- **SecretCore 起動・監視**：子プロセスとして起動、Named Pipe IPC + AES-256-GCM で通信
- **Task Scheduler 自動起動**：`AtLogOn + Interactive` で PC ログオン時に自動起動（`IoT_LocalServer_AutoStart`）

**実装場所**：[`IoT/LocalServer/src/`](IoT/LocalServer/src/) 配下（TypeScript）／ [`IoT/LocalServer/public/`](IoT/LocalServer/public/)（HTML/JS）／ [`IoT/LocalServer/scripts/`](IoT/LocalServer/scripts/)（PowerShell）

### 3.3 SecretCore（PC 側 Rust 秘密処理層）

| 項目 | 内容 |
|---|---|
| **役割** | LocalServer から分離された **秘密処理専用層**。鍵の生成・保管・導出、署名、暗号化/復号、高リスクワークフローの実行を担当 |
| **実装言語** | Rust（Release + LTO + strip + zeroize 適用、`Cargo.toml` で `codegen-units=1` / `panic=abort` / `strip=symbols`） |
| **OS 暗号化サービス** | **Windows DPAPI**（`CryptProtectData` / `CryptUnprotectData`、`WRAPPED_SECRET_ALG="DPAPI"`）。チップ非依存、ソフトウェア暗号化のみ。Mac/Linux 汎用化は `020-0004` |
| **主要技術** | `hmac` / `sha2` / `hkdf`（HMAC-SHA256 / HKDF）、`aes-gcm`（AES-256-GCM）、`rand`（CSPRNG）、`scrypt`（パスワード派生）、`winapi`（DPAPI）、`tokio`（非同期）、`rumqttc`（MQTT publish/subscribe）、Named Pipe |
| **依存モジュール** | LocalServer（IPC で依頼を受ける） |

**機能一覧（主要なもの）**

- **`S_random` の管理**：CSPRNG で 32 byte 生成、DPAPI でラップして `wrapped_secret.bin` へ保存。起動時に DPAPI 復号で復元
- **`k-user` の導出**：`S_random` から HKDF-SHA256 で導出（`info="k-user-v1"`、`salt="LocalServer"`）
- **`k-device` の導出**：`k-user` から HMAC-SHA256(`target_device_name=publicId`) で 32 byte 直接導出（**HKDF ではなく HMAC 直接**、`鍵管理および初期セットアップ設計仕様書.md` §6.2）
- **`k-user` バックアップ**：scrypt + AES-256-GCM で `k-user-backup.enc.json` を出力、別 PC 復旧用パスワード保護
- **command 署名**：`sign_by_k_device`（HMAC-SHA256）。OTA 開始・重要設定変更などの高リスク command で必須
- **payload 暗号化/復号**：`encrypt_by_k_device` / `decrypt_by_k_device`（AES-256-GCM、nonce/tag 検証付き）
- **高リスクワークフロー実行**：`runPairingSession()`（初回ペアリング）／ `runKeyRotationSession()`（鍵更新）／ `runProductionSecureFlow()`（不可逆セキュア化、dry-run まで）／ `runSignedOtaCommand()`（OTA 署名）。状態は `queued → running → waiting_device → verifying → completed/failed`
- **MQTT publish/subscribe**：LocalServer から委譲された command publish と notice subscribe（Stage1-Stage7、責任を Rust 側へ寄せる移行中）
- **IPC 保護**：起動時に LocalServer 親プロセスがランダム Pipe 名 + 32 byte セッション鍵を生成 → stdin で 1 回だけ SecretCore へ渡す → 以後は Named Pipe + AES-256-GCM + nonce で通信

**実装場所**：[`IoT/SecretCore/src/`](IoT/SecretCore/src/) 配下。主要ファイルは `main.rs` / `key_manager.rs`（鍵管理本体）/ `dpapi.rs`（DPAPI ラッパ）/ `pairing_workflow.rs` / `mqtt_transport.rs` / `ota_workflow.rs` / `generic_workflow.rs`

### 3.4 ProductionTool（PC 側 Rust 工場ツール）

| 項目 | 内容 |
|---|---|
| **役割** | メーカー専用ツール。**LocalServer と完全分離**。製造・初回書込み・初回セキュア化（Flash Encryption / Secure Boot v2 / eFuse 封鎖）・出荷可否判定ログ保存を担当 |
| **実装言語** | Rust（CLI ウィザード形式） |
| **依存モジュール** | LocalServer（任意：監査経由）／ ESP32（直接：シリアル / AP 経由）／ `espefuse` / `espsecure` / `esptool`（ホストツール） |
| **配布** | Inno Setup で `ProductionToolSetup.exe`（`020-0010` で本格化予定）／ 現在は CLI 単体 |

**機能一覧（主要なもの）**

- **PT-001 起動 + 追加認証**：メーカーモード専用パスワード（AP 共通パスワードとは別）で進入制御
- **PT-002 対象機確認**：シリアル番号、MAC、作業指示番号の照合（`PC-004` 照合）
- **PT-003 実行内容確認**：何を焼くか（FE 鍵 ID / SB 署名素材 ID / ロット）の確認ウィザード
- **PT-004 dry-run**：実コマンド実行なしで段階順序・必要環境変数・証跡保存先を表示
- **PT-005 段階実行（precheck → stage_execute → readback → evidence → stability）**：4 段階（FE → NVS 暗号化なし確認 → SB → 封鎖）を順次実施、各段階で読戻し・4 点証跡・安定性確認（OTA × 2、AP 10 分、STA 10 分）
- **PT-005a 監査経路**：LocalServer の `/api/workflows/production/start` 経由で監査ログを記録
- **PT-005z 実ランナー**：`PRODUCTION_TOOL_ENABLE_IRREVERSIBLE_COMMAND_RUNNER=1` + `PRODUCTION_TOOL_ALLOW_IRREVERSIBLE_EXECUTION=1` の二重ゲート、`espefuse` 等を起動して証跡保存（**現在は最小実ランナー、本格運用は `020-0011`〜`020-0013` で実装**）

**実装場所**：[`IoT/ProductionTool/src/`](IoT/ProductionTool/src/) 配下。主要ファイルは `main.rs` / `irreversible_stage_plan.rs` / `irreversible_command_runner.rs` / `pc004_check_state.rs` / `production_workflow_handoff.rs`

[重要] **本番1台目（`007-B` 不可逆処理）は現在 No-Go 継続中**。`ProductionTool` 最終形実ランナー完成と入口ゲート充足まで実行しない。詳細は `020-0011`（旧 `007-0001`）参照。

## 4. 通信経路一覧

通信経路は **5 種類**。それぞれ目的と保護方式が異なる。

### 4.1 MQTT TLS（8883）：ESP32 ↔ Mosquitto ↔ LocalServer

| 項目 | 内容 |
|---|---|
| **目的** | 通常運用のメッセージ通信（状態通知、コマンド送信、設定更新指示） |
| **方向** | 双方向（pub/sub） |
| **保護** | **TLS 1.2+** で通信路を暗号化／ ID/Password 認証で接続を制限／ ACL でトピック単位の認可／ payload は AES-256-GCM で **二重暗号化**（k-device 鍵、nonce/tag 検証）／ 高リスク command は HMAC-SHA256 で署名 |
| **トピック例** | `esp32lab/notice/status/IoT_04CEF94EB580`（状態通知）／ `esp32lab/set/relay/IoT_04CEF94EB580`（リレー制御）／ `esp32lab/network/update/IoT_04CEF94EB580`（Wi-Fi 設定更新） |
| **メッセージ形式** | JSON（共通ヘッダ + 暗号化 payload）。詳細は `MQTTコマンド仕様書.md` §3 |

### 4.2 HTTPS OTA（4443）：ESP32 → LocalServer

| 項目 | 内容 |
|---|---|
| **目的** | ファームウェア更新（manifest + firmware.bin 取得） |
| **方向** | ESP32 から LocalServer へ GET リクエスト |
| **保護** | **TLS 1.2+**、サーバ証明書検証、firmware に SHA-256 ハッシュと署名（メーカー署名） |
| **シーケンス** | MQTT で OTA 開始 command（署名付き）→ ESP32 が HTTPS で manifest 取得 → firmware.bin ダウンロード → 検証 → `app1` partition 書込み → 再起動 → `otadata` 切替 → 安定確認 → 確定（失敗時は rollback） |

### 4.3 AP モード HTTP（192.168.4.1）：ESP32 ← PC

| 項目 | 内容 |
|---|---|
| **目的** | 初回ペアリング、現地復旧、メンテナンス時の設定変更 |
| **方向** | PC（LocalServer or ProductionTool）から ESP32（AP モード）へ HTTP |
| **保護** | **WPA2 + 固有パスワード**（`AP_WIFI_PASSWORD`）／ Web UI 4 ロール認証（user / maintenance / admin / mfg）／ pairing bundle は P-256 ECDH + 固定公開鍵検証 + AES-256-GCM |
| **トリガー** | 起動時ボタン 3 秒長押し ／ MQTT `call/maintenance` 受信 ／ Wi-Fi/MQTT 必須設定未投入時の自動遷移 ／ 救済専用ビルド `APP_SECURE_RESCUE_MODE=1` |
| **エンドポイント例** | `POST /api/auth/login`（ロール認証）／ `GET /api/settings/network`（現設定取得）／ `POST /api/pairing/transport-handshake`（ECDH 鍵交換）／ `POST /api/production/precheck`（製造前確認） |

### 4.4 IPC Named Pipe + AES-256-GCM：LocalServer ↔ SecretCore

| 項目 | 内容 |
|---|---|
| **目的** | LocalServer から SecretCore への秘密処理依頼（鍵導出・署名・暗号化・workflow 開始） |
| **方向** | 双方向 |
| **保護** | ランダム Pipe 名（`\\.\pipe\iot-secret-core-<machineId>-<sessionId>`）／ DACL で LocalServer 実行ユーザー SID のみ ReadWrite ／ 起動時に親が 32 byte セッション鍵を生成し stdin で SecretCore へ 1 回だけ渡す ／ 以後は AES-256-GCM + nonce + requestId で payload 全体を保護 |
| **詳細** | `LocalServer秘密処理別層仕様書.md` §6 |

### 4.5 ローカル CLI：ユーザー ↔ ProductionTool

| 項目 | 内容 |
|---|---|
| **目的** | 製造・初回セキュア化のウィザード操作 |
| **方向** | ユーザー → ProductionTool（標準入力）、ProductionTool → ユーザー（標準出力） |
| **保護** | OS のローカルログオン保護のみ（追加でメーカーモード専用パスワード認証）／ 不可逆コマンドは二重環境変数ゲート |

## 8. 鍵階層と保護方式（概要）

```text
PC（Windows）
 │ OS 暗号化サービス（現行: Windows DPAPI、Mac/Linux 汎用化は 020-0004）
 │  + ユーザーアカウント拘束
 │
 ├─ S_random（32 byte CSPRNG、wrapped_secret.bin として保存）
 │   │
 │   └─ HKDF-SHA256 + salt="LocalServer" + info="k-user-v1"
 │       │
 │       └─ k-user（ユーザー環境のルート鍵、メモリ上のみ）
 │           │
 │           └─ HMAC-SHA256(message=target_device_name=publicId)
 │               │
 │               └─ k-device（デバイス単位通信鍵、メモリ上のみ）
 │                   │
 │                   ├─ AES-256-GCM payload 暗号化／復号
 │                   └─ HMAC-SHA256 command 署名／検証
 │
 └─ k-user-backup.enc.json（scrypt + AES-256-GCM、パスワード保護、別 PC 復旧用）

ESP32 側
 │
 └─ NVS（current/previous の 2 スロット）
     ├─ currentKDevice（ペアリング時に AES-256-GCM bundle で受領）
     └─ previousKDevice（鍵更新時に grace 期間保持、48h で expired-retained、240h で削除）

工場・製造側（不可逆）
 │
 ├─ k-iot-secure-boot（Secure Boot v2 署名鍵、当面は試験用と同一、本番分離は 020-0001）
 ├─ k-iot-flash-encryption（Flash Encryption 鍵、当面は試験用と同一）
 └─ k-iot-ota-sign（OTA firmware 署名鍵、メーカー保管）
```

詳細は `鍵管理および初期セットアップ設計仕様書.md` §3 / §6 と `鍵一覧仕様書.md`。

## 9. 用語ミニ辞典（初心者向け）

| 用語 | 説明 |
|---|---|
| **MQTT** | IoT 機器間メッセージ通信の軽量プロトコル。pub/sub 型。Mosquitto はその OSS 実装 |
| **TLS** | 通信路の暗号化・認証技術。Web の HTTPS や MQTT/TLS で使用 |
| **AES-256-GCM** | 256 bit 鍵の認証付き暗号化方式。改ざんを検知できる（tag 検証）。本システムでは payload 全体や AP bundle で使用 |
| **HMAC-SHA256** | 共有鍵によるメッセージ認証コード。署名検証で使用 |
| **HKDF** | 鍵導出関数（Key Derivation Function）。HMAC を 2 段（extract / expand）して目的別鍵を生成 |
| **DPAPI** | Windows Data Protection API。ユーザー資格情報で保護される暗号化。チップ非依存 |
| **NVS** | ESP32 の Non-Volatile Storage。少量の運用設定や鍵を永続化 |
| **LittleFS** | ESP32 のファイルシステム。画像・証明書・ログなどを保存 |
| **eFuse** | ESP32 の 1 回だけ書き換え可能なメモリ。Secure Boot 公開鍵や Flash Encryption 鍵などの不可逆設定を焼く |
| **Flash Encryption（ROM 暗号化）** | フラッシュメモリ上のファームウェアを暗号化し、抜き取られても解読不能にする ESP32 機能 |
| **Secure Boot v2** | ESP32 起動時に bootloader → app が改ざんされていないか公開鍵で検証する仕組み |
| **OTA Rollback（旧称「Dual バンク」）** | 起動失敗時に旧 partition（`app0`）へ自動復帰する仕組み（`BOOTLOADER_APP_ROLLBACK_ENABLE`、dual app partition `app0`+`app1`） |
| **AP モード** | ESP32 を Wi-Fi アクセスポイントとして動作させ、PC が直接接続できるモード |
| **STA モード** | ESP32 を Wi-Fi クライアントとして動作させ、既存 AP に接続するモード（通常運用時） |
| **publicId** | デバイスの公開識別子。初期値は `IoT_<MAC コロン除去>`（例: `IoT_04CEF94EB580`） |
| **k-user / k-device** | ユーザー環境の根本鍵 / デバイス毎の通信鍵（HMAC-SHA256 で導出） |
| **wrapped_secret** | `S_random` を DPAPI で暗号化して保存した物。`wrapped_secret.bin` |
| **ペアリング** | PC と ESP32 を初めて結びつける作業（AP モード経由で鍵と設定を投入） |
| **eFuse 封鎖** | JTAG / シリアル接続を不可にする eFuse 操作（出荷時の最終ロックダウン） |
