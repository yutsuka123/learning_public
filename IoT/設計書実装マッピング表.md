# 設計書 ↔ 実装マッピング表

[重要] 本書は **IoT プロジェクトの技術項目について、設計書のどこに書いてあるか／実装のどこに書いてあるか／どの試験で検証されているかを 1 つの表で参照可能にする** 横串リファレンスである。  
理由: 再設計や移管時、新規参画者の onboarding、設計と実装の齟齬チェック、試験範囲の漏れ確認を、文書を横断して個別に grep せずに済ませるため。

[読み方] **「技術項目」** で検索 → **「設計書」** で根拠を確認 → **「実装」** でコードを読む → **「試験 ID」** で検証状況を確認、の順で使う。

[厳守] 行番号は本書作成時点（2026-05-19）のもの。コードが変わると行が動くので、関数名と併記してある場合は **関数名で grep する** こと。

[関連] 本書は **概念解説と統一フォーマット詳細** を `セキュア全般ノウハウ_設計から実装まで.md` で、**システム全体像** を `システム構成と通信フロー.md` で扱う。本書はそれらの「インデックス」と位置づける。

## 7. LocalServer / SecretCore 連携

### 7.1 IPC（Named Pipe + AES-256-GCM）

| 項目 | 内容 |
|---|---|
| **設計書** | `LocalServer秘密処理別層仕様書.md` §6 |
| **Pipe 名** | `\\.\pipe\iot-secret-core-<machineId>-<sessionId>` |
| **DACL** | LocalServer 実行ユーザー SID のみ ReadWrite、Everyone / NETWORK SERVICE 拒否 |
| **セッション鍵** | 親プロセスが 32 byte ランダム生成、stdin で 1 回だけ SecretCore へ渡す |
| **業務 IPC** | AES-256-GCM + nonce + requestId + timestamp（±30 秒以内） |
| **AAD 形式** | `v=1\|rid=<requestId>\|ts=<timestamp>` / `v=1\|rrid=<requestId>\|ts=<timestamp>` |
| **実装ファイル** | `IoT/SecretCore/src/main.rs`（受信）／ `IoT/LocalServer/src/secretCoreManager.ts` / `secretCoreFacade.ts` / `secretCoreIpcClient.ts`（送信） |
| **互換モード** | `SECRET_CORE_IPC_SESSION_KEY_B64` 未指定の手動起動時のみ平文 IPC 許可（通常運用では使用しない） |
