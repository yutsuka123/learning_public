# APメンテナンス画面仕様書

[重要] 本書は ESP32 の AP メンテナンスモード（`http://192.168.4.1/`）の画面仕様、認証ロール、起動条件を定義する。  
理由: 現地復旧と製造保守で同じUIを使うため、権限制御と表示項目を先に固定して実装ブレを防ぐため。

[厳守] APモード中は MQTT タスクを起動しない。通常モード専用タスク（クラウド接続前提タスク）も起動しない。  
理由: APモードは局所メンテナンス専用であり、通常運用経路と同時起動すると誤操作とリソース競合を招くため。

[厳守] APモード ⇔ 通常モードの切替は、原則として再起動を伴う。  
理由: タスク起動構成、ネットワークスタック構成、認証状態を確実に初期化するため。

[厳守][2026-03-19] AP 共通トップ画面と `ProductionTool` 画面は分離し、eFuse / Secure Boot / Flash Encryption の操作入口を AP 画面へ混在表示しない。  
理由: 通常保守画面と工場内高リスク操作画面の境界を維持するため。

## 1. APモード遷移条件
- [厳守] 起動時ボタン3秒長押しで AP モードへ入る。
- [厳守] MQTT `call/maintenance` 指令受信時は、次回起動を AP モードにして再起動する。
- [厳守] Wi-Fi / MQTT の必須設定未投入（SSIDや broker 情報欠落）時は、自動で AP モード起動する。

## 1.1 AP モードの有効性とセッション境界
[厳守][2026-05-19] 初回ペアリング／AP メンテナンスは **単発セッション**として運用する。攻撃面の縮小は **次の 5 層**で達成し、別途のセッションタイマー（N分無操作で自動終了）は要件としない。

| 層 | 内容 | 実装 |
|---|---|---|
| ① 物理操作必須 | 起動時ボタン3秒長押し（または起動後30秒以内の長押し）でしか AP モードへ入れない | `IoT/ESP32/src/main.cpp:539 detectStartupMaintenanceLongPress` / `IoT/ESP32/src/input.cpp:109-115 handleLongPressEvent` |
| ② Wi-Fi 認証必須 | SoftAP は WPA2 + 固有パスワード（`AP_WIFI_PASSWORD`） | `IoT/ESP32/src/main.cpp:502` |
| ③ Web UI 認証必須 | 4 ロール（user / maintenance / admin / mfg）の Web UI ログイン必須 | `IoT/ESP32/src/maintenanceApServer.cpp` / 本書 §4 |
| ④ 通常通信からの隔離 | AP モード中は STA / MQTT 通常タスクを起動しない（無限ループで AP 専用処理のみ実行） | `IoT/ESP32/src/main.cpp:524-532` |
| ⑤ 単発有効（持ち越さない） | `requestMaintenanceModeOnNextBoot` 経由の AP モードフラグは次回起動時に消費して `false` へ戻す。AP モードを抜けるには **ボタン長押し → 再起動** を要し、再起動後は通常モードに復帰する | `IoT/ESP32/src/maintenanceMode.cpp:51-64 consumeMaintenanceModeRequest` |

[補足][2026-05-19] `todo.md` `009-0018`（初回ペアリングAPモード「物理操作必須、短時間有効」）の「短時間有効」は本節の **「単発有効＋手動終了経路あり」** として実装・整合済み（`todo_old20260519.md` 参照）。攻撃継続を避けるための「N分無操作で自動切断」のセッションタイマーは要件としない。理由: ペアリング作業中に強制切断されると現地復旧の運用負荷が増えるため、物理操作・認証・隔離・単発有効の 4 層で攻撃面を縮小する設計を採用する。

## 2. APモード表示仕様
- [厳守] 電源LED（青）パターン:
  - 0.3s ON -> 0.3s OFF -> 0.3s ON -> 0.3s OFF -> 1.0s ON -> 0.3s OFF を繰り返す。
- [厳守] LCD 1行目に `MaintenanceMode` を表示する。
- [推奨] LCD 2行目に AP 名（16文字以内）を表示する。

## 3. APネットワーク仕様
- AP URL: `http://192.168.4.1/`
- SSID: `AP-esp32lab-<MAC(no colon)>`
- AP パスワード: `IoT/LocalServer/.env` の `AP_WIFI_PASSWORD`

## 4. 認証ロール仕様
[重要] 下記は初期ロール定義である。運用段階では変更可能とし、固定値の継続利用は避ける。

[推奨] 下記パスワード（初期値）は、初回ログイン時または運用開始前に変更する。  
理由: 固定値の長期運用リスクを下げつつ、現場事情に応じた段階導入を可能にするため。

[推奨] AP Web UI ロール別パスワードに限らず、LocalServer 管理者パスワードや関連サービス認証情報も同様に変更運用し、変更履歴（対象・日時・実施者・理由）を監査ログへ残す。

| ロール | user | password（`.env` 参照） | 主な権限 |
|---|---|---|---|
| 閲覧用 | `user` | `IoT/LocalServer/.env` の `AP_ROLE_USER_PASSWORD` を参照 | メイン画面の閲覧のみ |
| メンテナンス者 | `maintenance` | `IoT/LocalServer/.env` の `AP_ROLE_MAINTENANCE_PASSWORD` を参照 | メイン画面、ネットワーク設定変更 |
| 管理者 | `admin` | `IoT/LocalServer/.env` の `AP_ROLE_ADMIN_PASSWORD` を参照 | メンテナンス者権限 + `k-device` + MQTT証明書設定 |
| メーカー | `mfg` | `IoT/LocalServer/.env` の `AP_ROLE_MFG_PASSWORD` を参照 | 管理者権限 + ProductionTool 起動案内（eFuse 設定は実行しない） |

## 5. 画面仕様
### 5.1 メイン画面
- デバイス名
  - 初期値: `IoT_<MACコロン除去・大文字>`
  - 変更可
  - 文字種: 英大/英小/数字/`_`/`-`/`+`
  - 先頭: 英字のみ
  - 最大: 32文字
- サブデバイス名
  - 固定: `IoT_<MACコロン除去・大文字>`
- FWバージョン
- FSデータバージョン
- 接続先情報（読み取り表示）
  - Wi-Fi AP 名
  - MQTT broker（IP / 名前 / Port）
  - Server（IP / 名前 / Port）
  - OTA（IP / 名前 / Port）
  - NTP（IP / 名前 / Port）
- [厳守] 「詳細設定」ボタンは `maintenance` 以上で表示・操作可能とする。

### 5.2 詳細設定画面
[重要] ログインロールにより、表示・編集できる項目を制御する。

- 共通表示:
  - デバイス名、サブデバイス名、FW版、FS版
- `maintenance` 以上:
  - Wi-Fi / MQTT / Server / OTA / NTP の host/name/port/user/password
  - 必要に応じ証明書アップロード
- `admin` 以上:
  - `k-device` 発行番号表示
  - `k-device` 暗号化ファイルアップロード
  - MQTT 証明書設定
- `mfg` のみ:
  - ProductionTool で実施すべき高リスク操作の事前確認情報表示（対象機識別、状態確認）
  - [厳守] eFuse / Secure Boot / Flash Encryption の実行ボタンは表示しない

- 操作ボタン:
  - 設定
  - キャンセル
  - 再起動
  - 設定の確認

[厳守] 「設定の確認」ボタンは「通常モードへ再起動して接続確認（mqtt/ntp/k-device有効性）後、APモードへ再起動して結果表示」を行う。

## 6. API権限制御（画面連動）
- [厳守] 未認証:
  - 設定参照不可
  - 設定更新不可
  - FW更新不可
  - 画像更新不可
- [厳守] `user`:
  - 読み取りのみ（メイン画面）
- [厳守] `maintenance`:
  - ネットワーク設定更新可
- [厳守] `admin`:
  - `maintenance` + `k-device` / MQTT証明書設定可
- [厳守] `mfg`:
  - `admin` + ProductionTool 事前確認情報の表示可（eFuse 操作不可）
